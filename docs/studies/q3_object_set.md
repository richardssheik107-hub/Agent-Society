# Q3｜是否保留规范对象集

状态：历史单步实验已完成，支持 Catalog + Top-K 作为当前工程参考；Hybrid 未通过接受门槛。原始结果不因本次整理而改变。[证据 E-Q3](../reference/evidence.md#q3)

## 问题为什么重要

“我想吃牛角包”只是意图；系统还需要知道对象是否存在、有哪些效果字段、参数从哪里来。取消对象库不会让这些问题消失，只会把责任转移给模型临时生成。因此我们比较的是**单次对象选择的接口可执行性与属性来源**，不是直接测试真人生活质量。

## 三个方案与控制条件

| 方案 | 模型能看什么、能输出什么 | 属性来源 |
|---|---|---|
| A：LLM_ONLY | 不看目录，自行命名具体对象 | 模型估计，按类型/范围检查 |
| B：CATALOG_TOPK | 只能选择检索出的目录候选 | 使用目录正式属性 |
| C：HYBRID | 选目录对象，或 `NEW:<name>` 并补齐必要属性 | 目录或模型估计，分别标记 |

相同固定场景；每行一次 `{"object":"...","attributes":{...}}`，不做第二次修复请求、不模糊修复。目录规模 1,000，Top-K=10。5 领域×6 状态×3 方案×2 重复，共 180 请求。先前 Attempt 1 的 15 个 HTTP 错误保留；Attempt 2 的 smoke 为 14/15 成功，完整运行 162 成功、18 超时、HTTP/解析/架构错误均 0。成功响应标识为 `glm-5.3`，超时后端未知。

## 比例到底怎么算

每个场景×重复对应 A/B/C 三个请求。主要比较只保留三者均成功的 43 组，各方案分母都是 43，不是 180 或 162。

| 方案 | 通过数/共同案例数 | 运行时可执行率 | 可用效果字段覆盖 | 目录来源字段覆盖 | 模型估计字段率 |
|---|---:|---:|---:|---:|---:|
| A | 13/43 | 30.23% | 72.87% | 0% | 100% |
| B | 43/43 | 100% | 100% | 100% | 0% |
| C | 38/43 | 88.37% | 96.12% | 41.86% | 58.14% |

“可执行”是本基准的对象解析、必要字段和有界检查结果，**不是完整世界已真实执行了 43 次长期活动**。配对排除了各臂样本构成不一致的一部分影响，但不能消除非随机超时造成的选择偏差。

全部成功行另为 A=60、B=51、C=51，对应可执行率 28.33%、100%、90.20%，不能与上表混用。C 的 NEW 比例 58.8235% 属于全部 51 个成功行；共同 43 组的模型估计字段率为 58.1395%。原译文曾把这两个分母混写，本页按表格口径澄清，不覆盖历史原文。

## 效果与成本的取舍

配对可执行率 B 比 A 高 69.77 个百分点，比 C 高 11.63 个百分点。C 的灵活性有收益，但尚未保住 B 的接口稳定性，故 `hybrid_open_world_signal=UNRESOLVED`（语义标签保留，实际字段以历史实现为准）。

全部成功行的平均输入 token 约 A=121.57、B=366.90、C=382.02；平均延迟约 8.16、16.46、19.17 秒。这些不是等分母配对成本，也不是稳定性能保证。目录信息有成本，Top-K 的价值是控制每次暴露量，而非声称免费。

“权威”仅指来自目录，不指合成价格、热量真实正确；A=0、B=1 部分由实验来源定义直接决定，不能把这项再算成独立行为改善证据。“合理”仅通过有界校验，也不是真实知识核验。

## 当前决定与人工边界

保留规范对象 ID 与目录，用少量候选让模型选择；不把自由创建作为当前默认执行通道。工程信号 `object_set_necessity_signal=STRONG` 仅覆盖受测模型、提示、合成目录和单步协议。没有证明所有任务都必须有目录、Hybrid 永远无效或长期进度已经可靠。

对象全量呈现、每个世界固定小目录、动态上下架与用户偏好检索仍需[人工 D-03](../review/decisions.md#d-03)。目录选出对象不代表该人物当前能使用它，这正是[Q6.2](q62_action_projection.md)的新问题。
