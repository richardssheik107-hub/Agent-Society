# 三个会议问题：目前有什么证据

## 问题一：是否保留对象集？

Q3 比较了模型自行生成对象与属性、目录 Top-K、允许 NEW 的混合方案。报告中的 43 组共同成功样本，可用字段与协议检查通过率分别为 13/43、43/43、38/43。当前选择 **Catalog + Top-K** 作为工程参考。

这证明的范围是该模型、该提示和合成目录下的一步接口可靠性，不是任何模型都不能生成对象，也不是 100% 的真人合理性。目录“authoritative”只表示参数来自目录，不代表其合成价格/热量在现实中正确。目录、身份和长期持久状态是不同层，Q3 没有验证跨天进度。

原始报告：[Q3 Attempt 2](../archive/2026-09-20/research_q3_object_set_necessity_real_attempt2.md)。

## 问题二：人物要看多少状态？

Q4 固定底层事实，只改变可见字段的 R8/R16/R32/R64，192 次计划请求中 174 次返回，33 组四臂共同成功。人工场景匹配率约为 69.7%、72.7%、72.7%、84.8%；输入 token 约为 281、346、477、747。

R16→R32 在这一次实验中增加成本而没有观察到匹配率收益。但“字段数量”和“具体加了哪些字段”同时改变，不能据此宣布任何 32 字段都无用，也不能把 R8→R16 一次样本的增益说成稳定规律。

最小可用字段集合仍为 **UNRESOLVED**。群体日记的活动频率不是给定强需求情境下的“真人正确答案”，held-out share 下降不能直接等同于“不像真人”。动态相关字段投影仍只是待测假设，尚未完成检索消融。

原始报告：[Q4](../archive/2026-09-20/research_q4_resource_set_size.md)。

## 问题三：对象多了，规则关系怎么维护？

Q5 用虚拟整数对象 ID、固定类型与能力，验证了共享规则索引无需为每个对象复制规则。10M 虚拟地址空间下，类型—规则索引 21 项、能力—类型索引 28 项；显式关系数量按所设 schema 计算为 7,500 万。

这是**虚拟目录上的规则适用性查找微基准**。对象类型由 ID 算术规则确定，候选也是确定性 ID 采样，不是检索真实千万行目录。17KB 是小索引估计，不包含实体数据；约 35 微秒不是实际商品搜索或完整动作执行延迟。`CLOSED_ENGINEERING` 是旧程序对这个狭窄结构门槛的名称，不等于完整规则系统已经完成。

选择共享 Type/Capability/Rule Template 作为设计方向合理，但动态合法性、对象参数、事务、异常和实际状态后果必须另测。Q6 已开始补齐这个缺口。

原始报告：[Q5](../archive/2026-09-20/research_q5_rule_engine_scaling.md)。

## 当前优先级为何改变

我们不再继续放大纸面世界，而优先检查：同一对象有没有稳定身份，吃完库存有没有消耗，看完进度有没有保存，重启有没有回到初始状态，重复提交有没有重复扣钱。
