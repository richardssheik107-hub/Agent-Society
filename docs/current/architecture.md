# 规则体系与长期状态设计

## 一、四个集合仍然分工明确

**对象集**保存具体对象的身份和参数；**动作集**定义可以提出的操作；**资源/状态集**保存人和世界的事实；**规则集**判断能不能执行、怎样计算后果。类型与能力用于找到适用规则，但“有 edible 能力”不意味着现在一定能吃——仍要检查拥有量、活动冲突等前置条件。

当前 Q6 用 `ObjectDefinition` 表示对象，用 SQLite 中的人物、库存、人物—对象关系和活动记录保存动态事实。原有 `WorldState` 仅通过 AS2 适配器导出为只读兼容投影，不建立两个互相覆盖的真值来源。

## 二、通用公式不等于所有对象效果相同

规则决定怎么算，对象参数决定变化多少。本轮全部数值是**合成测试参数**，不代表真实价格或营养事实。

- 购买：`money_cents -= price_cents`，库存增加一份，卖家库存减少一份。
- 食用：`hunger_milli = max(0, hunger_milli - satiety_milli)`，摄入热量增加 `calories_kcal`，持有量减少一份。
- 购买扣钱，食用不再扣钱；卡路里累计与疲劳/精力不是同一个变量。

`RuleParameters` 保存公共规则参数和版本；打开已有存档时自动复用保存的参数，显式换参数必须另做迁移，不会静默改变后果。对象参数由 `ObjectDefinition` 提供。

金额用整数分，需求用 0～1000 整数，时间用从固定起点开始的整数模拟分钟，避免隐含单位和浮点累计误差。当前只实现单一模拟货币，不包含汇率、授信或房产估值。

## 三、目录属性与“我做过什么”分开

电视剧总集数、单集时长是目录属性。Alice 看到了第几集、某集已看了几分钟，是以 `(actor_id, object_id)` 为键的稀疏关系状态。

关系状态包括 `quantity`、`watched`、`offsets`、`view_counts`、`play_minutes`。不同人物不共享观看进度；别名统一映射到同一个正式对象 ID。没有发生交互的对象不需要为每个人预建状态行。

默认 WATCH 选择下一未完成集；看一半会保存 offset，取消后仍可以断点续看。已完成集在普通继续模式下不能被当作新集再次完成。显式 `rewatch=True` 允许正常重看，增加观看次数但不倒退主线进度。顺序播放是本测试连续剧的产品策略，不宣称人类不能跳集。

## 四、活动有生命周期，不靠计划时间伪造完成

模型只提交当前一项高层意图。例如 `MEAL(food_meal)` 形成一个活动承诺，控制器根据实际状态执行必要步骤：前往卖家、购买、食用。每步仍由规则验证。若已拥有食物，不再次购买。

状态流转：`ACTIVE → COMPLETED / FAILED / CANCELLED`；`ACTIVE ↔ PAUSED`。一个人物最多有一个 ACTIVE 或 PAUSED 活动。

WATCH 只有累计实际观看时长达到单集时长才标记完成。暂停期间即使跨了一天，也不推进媒体进度。运行期间只推进控制器，不重复调用模型。下架事件使相关活动失败并保留实际完成的进度，不把它伪装成成功。

当前支持 MEAL、WATCH、PLAY、TRAVEL、WORK、SLEEP、LEISURE、PERSONAL_CARE、CHORES。原子 MOVE/BUY/EAT 只保留为兼容/对照接口。MEAL 内旅行 15 分钟、食物占用时长、被动需求变化、工作收入等都是明确写出的工程参数；尚未做行为学/生理学联合校准。当前 WORK 等持续活动主要验证时间和状态一致性，不能把所有动作都说成已有完整需求恢复模型。

## 五、事务、幂等与恢复

事实修改、活动进度、命令结果、领域事件在同一个 SQLite 事务内提交。每条命令带唯一 `request_id` 和参数指纹：

- 同一个 ID、同一组参数再次提交，返回原结果，不再次扣款或推进进度。
- 同一个 ID 换参数，拒绝为 `REQUEST_ID_REUSE`。
- 版本过期、库存不足、时间倒退等领域错误不提交部分后果。
- I/O 错误或进程在事务中退出，未提交更新回滚。
- 一个宏活动的已完成阶段是真实事实：到达餐厅后没钱买饭，会保留已发生的移动，而不声称整顿饭完成。

持久命令去重保证的是**已提交效果不重复**，不是声称外部 HTTP 在分布式故障下恰好发送一次。模型请求另有 `decision_attempts` 记录；失败或中断后默认不自动再请求。

SQLite 是本次单机、共享环境单写者的参考实现。它不是 AS2 的旧 replay `sqlite.db`，也不是千万对象的最终分布式方案。候选与决策上下文有界；审计快照和长周期离线验证可以读全量小世界状态。

## 六、和 AgentSociety 2 的接口

`ContinuityEnv` 继承原项目 `RuleWorldEnv`，因此可使用已有 `DeterministicRouter` 观察链路。适配器实现 AS2 的 `step`、`to_workspace`、`restore`：模拟时间推进实际活动；workspace 使用一致的 SQLite checkpoint；恢复不会用初始余额覆盖旧状态。

本轮没有重新启用 CodeGenRouter、PersonAgent/ReAct，也不额外使用记忆总结模型。借鉴 daily-guidance 的持续段思想，但区分**计划时间段结束**与**实际消费/观看完成**。公开的 AS2 hooks 默认可为空操作，不能因为存在 workspace 就假设自定义领域状态会自动保存。

## 七、能保证和不能保证的事

在已实现并通过测试的边界里，余额、库存、进度和命令去重是确定性的工程约束。它们不保证人物的偏好、情绪或每日安排一定像真实人类。

7/30 天脚本是在持续制造可核对的情境，验证基础机制没有忘记状态。下一阶段必须用受控真实模型决策验证自主连续行为，不能把脚本验收换一个标题就当成模型实验。
