## P0：长期事实与持续活动

已实现人物—对象稀疏状态、身份别名统一、参数化购买和食用、媒体部分进度、显式重看、活动暂停/继续/取消/失败、重复请求去重、过期版本拒绝、事务与账本核对、7/30 天脚本基准。固定上游的 AS2 薄适配器实际观察/时钟/checkpoint/restore 专项已通过。

这些是受测工程约束，不是长期人类行为真实性证明。旧 Phase/A2 的状态、时长和评估保持历史复现语义，不把 Q4 的影子字段塞进生产状态，也不把 Q5 虚拟索引当作真实目录数据库。

## P1：独立运行时预检，再做四步真实连续性

Attempt 1 的入口导入失败、Attempt 2 的请求尝试和清理异常均保留在 [原实验报告](q6_1_real_continuity_pilot.md)。它们没有建立真实模型的连续反馈证据。

本轮已补齐独立环境与安全预检代码，[实际离线验收](q6_1_provider_runtime_acceptance.md)记录 109 项联合专项通过、609 项全库通过和 8 项历史数据依赖跳过。真实火山预检和 Attempt 3 没有在本轮运行。

当前执行顺序：

```text
单一 .venv-q61-runtime + pip check
→ 无凭据本机 HTTP 回环
→ 一次真实 provider 预检
→ 仅在预检通过且显式 --with-pilot 授权后运行四次高层决策
→ 保存和审阅真实结果
```

具体命令与安全边界见 [运行时手册](q6_1_provider_runtime.md)。单个组合会话最多五次客户端尝试，其中一条是独立预检，不计为连续行为决策。不自动扩到十二次，不用 retry、修复请求、WAIT 或脚本动作隐藏失败。

检查模型提案→规则→实际时间推进→进度写回→下一次观察。请求成功不等于活动完成；观察变化不等于模型已因果利用状态；减少请求次数不等于更像真人。分别记录 provider、模型输出、规则、活动、状态反馈和清理阶段。

四步真实证据通过后才考虑另行授权更长短链，再逐步验证半天、一天、多天。不直接启动真实 7/30 天付费实验。

## P2：短上下文相关状态投影

先审计 Q4 哪些字段和场景决定差异，以及 held-out 指标的有效分母。然后固定预算比较精简固定字段与不依赖答案标签的相关字段投影。选择器不能读取 acceptable_action_set、场景答案或未来事件。

后台保存哪些真值、每次给模型看哪些字段是两个问题。先确定字段语义与任务边界，再精简数量，不把 8/16/32/64 当作普适常数。本轮未提前实现 Resource Retrieval。

## P3：实际目录与交付目标

保留共享规则模板，另测真实存储、价格/库存更新、对象上下架和非算术检索。维护规则版本、参数来源与迁移，不预先物化对象×动作×资源笛卡尔积。

对齐 19 类序列意图时，先规定少量目标实体和干扰实体。其他成员的 delivery 数据保留原样，尚未被本轮清洗或改标签。本地小模型对照需要明确部署与授权，使用相同状态、规则和预算，不能直接迁移远端模型结论。

## 执行纪律

安装依赖可以联网；离线测试不请求真实 provider。真实请求必须显式 opt-in，增量留痕。原始实验不补写成功、不覆盖失败；指标修订有独立版本。规则不接受模型任意代码或自造状态。阶段报告只记录实测，不强行 CLOSED。
