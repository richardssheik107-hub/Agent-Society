# 基础阶段：先让“观察—选择—规则—后果”连起来

阶段：Phase 0—8A。定位：历史工程基础，代码仍保留复现；不是现在继续执行的任务清单。

## 问题与做法

最初不直接构造庞大社会，而先建立一个小世界。只读观察告诉模型时间、位置和可用对象；模型返回结构化意图；确定性系统决定能否移动、买到食物、消耗库存及改变资源。

| 子阶段 | 核心工作 | 保留下来的价值 |
|---|---|---|
| 启动与只读世界 | 固定 AgentSociety 上游、自定义世界与观察入口 | 不让模型随意修改世界事实 |
| 紧凑决策 | 单次请求、受约束输出、上下文结构 | 把决策成本与工具/规则成本分开 |
| 确定性 MOVE | 验证角色、目的地和移动后果 | 行为意图与状态变更分离 |
| 午餐闭环 | MOVE→BUY→EAT | 钱、商品、位置和库存必须相互一致 |
| 实际闭环与轨迹 | 记录规则裁决和逐步状态，区分服务失败 | 失败可定位，而不是都叫“发呆” |
| 评估与上下文消融 | 比较上下文组织方式 | 为后来的最小支持实验提供工具 |

这些模块解释了我们为什么坚持“模型提议，代码裁决”，但不能据此声称当前本地 8B 已验收，文件名中的 8B 也不是实测通过证明。[依据：基础阶段原文登记](../reference/evidence.md#foundation)

## 对今天工作的影响

持续活动控制器不是取消低层规则，而是在原规则之上管理一段活动，避免普通午餐被拆成许多模型决策。短上下文也不意味着丢掉余额、库存等真值；后台持久保存，再选择可见投影。

代码检索：`world/`、`actions/`、`rules/`、`effects/`、`reducer/`、`execution/`、`router/`、`context/`、`evaluation/`，均位于 `src/social_sim/`。旧 `smoke/` 脚本用于复现，不应因名称出现“下一步”就重新发送请求。
